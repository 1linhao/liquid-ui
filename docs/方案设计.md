# LiquidUI 跨框架资源库方案

## 技术方案概述

LiquidUI 调整为“一个深 runtime Module + 多个薄 Adapter”。主题状态、材质能力检测、质量档位、Surface 意图、filter registry、缓存和浏览器降级集中在无框架 Module 内；原生 DOM 与 Vue 2 分别作为 Adapter，不复制核心 Implementation。现有根入口继续兼容 Vue 2 调用方，新项目应使用明确的子路径入口。

## 技术选型

| 类别 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | 原生 ESM JavaScript + `.d.ts` | 浏览器、SSR、构建工具均可消费，不绑定编译器 |
| 样式 | 标准 CSS Custom Properties | 可用于原生 HTML、React、Vue、Svelte 等项目 |
| 核心状态 | 注入环境的内存 runtime | 支持浏览器、SSR 与测试，不创建远程依赖 |
| DOM 适配 | 标准 DOM Interface | 提供零框架的第二个真实 Adapter |
| Vue 兼容 | Vue 2 options Adapter | 保持 Trojan Panel 当前迁移路径 |
| 发布 | 单包多子路径 exports | 避免多个包版本漂移，同时允许按需加载 |

## 架构设计

```text
@liqui/liquid-ui/core
  createLiquidRuntime()
       │
       ├── @liqui/liquid-ui/dom      原生 DOM Adapter
       ├── @liqui/liquid-ui/vue2     Vue 2 Adapter
       └── future react/vue3/svelte  后续 Adapter

styles/tokens.css → styles/base.css → styles/components.css → styles/utilities.css
```

核心 Module 的外部 Interface 只暴露 `runtime.theme` 与 `runtime.material`。SVG、Canvas、ResizeObserver、缓存键、浏览器 UA 和层级 DOM 都属于 Implementation。调用者只选择 `surface` 意图与质量档位。

## 模块划分

| Module | 职责 | 依赖 |
| --- | --- | --- |
| core | 创建 runtime，统一主题与材质控制 | 纯计算、可选浏览器环境 |
| material | 光学参数、能力检测、registry/cache 与降级 | 注入的 document/environment |
| dom | 创建完整 Surface DOM、更新与销毁生命周期 | core + material internal seam |
| vue2 | Vue 2 安装与 primitives | core + material internal seam |
| styles | token、基础、模块和工具样式 | 无 JavaScript 依赖 |

## Interface 设计

### core

```js
import { createLiquidRuntime } from '@liqui/liquid-ui/core'

const runtime = createLiquidRuntime({
  document,
  matchMedia,
  paletteStorage: localStorage,
  initialMode: 'system'
})

runtime.theme.setMode('dark')
runtime.material.setQuality('reduced')
```

### DOM Adapter

```js
import { createLiquidSurface } from '@liqui/liquid-ui/dom'

const surface = createLiquidSurface({
  runtime,
  document,
  surface: 'panel',
  content: 'Hello'
})

document.body.append(surface.element)
surface.update({ surface: 'overlay' })
surface.destroy()
```

返回值只包含 `element`、`contentElement`、`update()` 和 `destroy()`；层级 DOM 和测量顺序留在 Implementation 内。

### Vue 2 Adapter

```js
import { createLiquidUI } from '@liqui/liquid-ui/vue2'
Vue.use(createLiquidUI())
```

## 关键设计决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 多包还是单包 | 单包多入口 | 核心与 Adapter 版本必须同步，减少发布协调 |
| Vue 是否必需 | optional peer | core/DOM 消费者不应安装 Vue |
| 是否立即使用 Web Components | 暂不使用 | Shadow DOM、表单关联和主题穿透会扩大 Interface；DOM Adapter 已验证无框架复用 |
| 是否公开 filter registry | 不公开 | registry 是内部 seam，公开会迫使调用者学习缓存与浏览器细节 |
| 根入口行为 | 保持兼容 | 避免破坏当前 integration lab 与 Trojan Panel 后续迁移 |

## 测试策略

- core 在没有 `document` 和 Vue 的 Node 环境中通过 Interface 测试。
- DOM Adapter 使用内存 DOM Adapter 测试 Surface 创建、更新与销毁。
- Vue 2 继续通过安装与 primitives 契约测试。
- 新建纯原生消费者，依赖树中 Vue 为零，并完成生产构建和浏览器验收。
- 发布前对每个 exports 子路径执行真实 import smoke test。

## 删除测试

若删除 core，主题解析、palette 持久化、能力检测、质量降级和 Surface 参数规范化会重新出现在 DOM、Vue 2 及未来 Adapter 中，复杂度明显扩散；因此 core Module 具有 Depth。若删除 DOM Adapter，原生项目需要自行理解五层 Surface DOM 和 bind 生命周期，因此 DOM Adapter 同样提供有效 Leverage。

## 实现计划

1. 拆分 `core.js`、`dom.js`、`vue2.js` 并维护根入口兼容。
2. 增加独立 CSS 子路径与 optional Vue peer。
3. 为 core/DOM Interface 添加不依赖 Vue 的测试。
4. 创建 `liquid-vanilla-lab` 仓库验证零框架消费。
5. 完成构建、发布 dry-run、依赖扫描与真实浏览器验收。

# 阶段 C：选择控件与 Overlay Seam

## 技术方案概述

Select、DatePicker、Dropdown、Popover 和 Dialog 共享定位、窗口变化监听、外部点击、Escape 关闭与焦点恢复行为。先建立一个深 `AnchoredOverlay` Module，把这些行为藏在 `open()`、`close()`、`updatePosition()`、`destroy()` 四个方法后；Vue 2 Select 是该 DOM Interface 的第一个 Adapter，后续 DatePicker 和 Dropdown 直接复用。

Select 的公开 Interface 使用 `options` 数据而不是解析业务 slot DOM。单选和多选都保持 controlled：Module 只发出下一值，不修改调用方状态。键盘方向移动会跳过 disabled option，Enter/Space 选择，Escape 关闭并恢复触发器焦点。搜索、选项规范化和多选切换为纯函数，供不同 Adapter 复用。

## 关键设计决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| Overlay 放置 | DOM 子路径中的通用 Module | 定位和焦点依赖 DOM，但不依赖 Vue |
| 面板层级 | 原生 Popover API 渐进增强 + fixed fallback | 支持 top layer，同时保留旧浏览器可用性 |
| Select 数据 | 显式 `options` | Interface 稳定、类型清晰，不要求 Adapter 解析 vnode/slot |
| 值模型 | controlled | Form、store 和原生状态 Adapter 都能掌握唯一真值 |
| 材质 | 面板复用 `LiquidGlassSurface(surface="overlay")` | 所有悬浮层走同一材质 registry/cache 与降级路径 |

## 删除测试

若删除 `AnchoredOverlay`，Select、DatePicker、Dropdown 和 Popover 会分别重写监听注册、定位、关闭与焦点恢复，复杂度扩散到至少四个调用方；该 Module 因而提供明确的 Depth、Leverage 与 Locality。
